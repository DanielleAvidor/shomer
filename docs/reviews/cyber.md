# Shomer cyber review (adversary + architect). Code untouched. Attacks run via shomer.engine.Engine.

What holds: userinfo@, subdomain-prefix (x.leumi.co.il.evil.test), punycode/non-ASCII hosts, IP and dotted-quad, hxxp/[.], zero-width in hosts, backslash tricks, fragment/query tricks all return dont_click. Message text is not stored by server.py (DB holds verdict/org/host only). Manifest: allowBackup=false, only MainActivity/SmsReceiver/ShomerListener exported, receiver and listener guarded by system permissions, PendingIntents are FLAG_IMMUTABLE, ExplainActivity not exported.

## REJECTS

1. BLOCKER. Open redirect / user-content on official domains => "matches_official".
   Repro: `בנק לאומי https://leumi.co.il/redirect?url=https://evil.test שלמו` -> matches_official; same for israelpost.co.il/redirect?url=...; whole official subtrees (any subdomain, any path) are trusted (engine.py:_official_match, ~L205; only gov.il has restricted_paths). Also `www.gov.il/he/service/enforcement-reports@evil.test` and `.../enforcement-reports/../../x` -> matches_official (path prefix compared un-normalized, engine.py:_analyze_link restricted_paths check; browser normalizes `..`).
   Fix: (a) if query/fragment/path contains another URL, a host-like token, `url=`/`redirect`/`next=`/`returnUrl`/`goto` params, or `//`, downgrade to cant_verify with an explicit reason; (b) resolve dot-segments and percent-decode the path before restricted_paths prefix test, and require prefix + "/" or end; (c) per-org subdomain allowlist for orgs that host user content/campaign pages; (d) test cases for all of these in eval corpus (and Kotlin parity).

2. BLOCKER. ReDoS (quadratic) in directory.json signals `payment` and `prize` (`\d[\d.,]* ?(?:nis|ils|shekels?|₪) (?:fee|...)` and `\d+ ?(?:שקל|ש"ח|₪)? ?ביום`).
   Repro: `Engine().check("0501"*4000)` 0.9s; 8000 chars 2.1s; 16000 chars 8.5s (quadratic; 60 KB server cap = minutes of GIL-held CPU per request; ThreadingHTTPServer => all clients stall). Same patterns run on Android via java.util.regex in the SmsReceiver (goAsync, ~10s budget) and the NotificationListener, with no input length cap anywhere in ShomerEngine.kt (grep: no take/limit). A scammer can send a long digit string to make the agent time out/ANR = silent bypass of the very message that is scam.
   Fix: cap analysed text (e.g. first 4 KB + all URLs, flag "long message, could not fully check" => cant_verify); rewrite as `\d{1,12}(?:[.,]\d{1,3})*`; add a CI test that runs every signal on 20k-char adversarial strings under 50 ms in both engines; run Android check on a worker with hard timeout, fallback verdict cant_verify never silence.

3. MAJOR. Obfuscated text is not undone: `_SPACED` is defined (engine.py ~L190) and never used; no NFKC.
   Repro: `ב נ ק  ל א ו מ י דחוף https://evil.test/pay` -> cant_verify, certain=False, org unclaimed (vs dont_click for the unspaced text). `ＬＥＵＭＩ https://evil.test`, `𝐋𝐞𝐮𝐦𝐢 ...`, `Leumi<ZWSP>bank ...` (prepare strips ZWSP but claimed_orgs only after the strip... still English alias needs word boundary; "Leum1" / "ליאומי" also evade) -> cant_verify. Fully spaced scam with card-credential wording + link: `ה ח ש ב ו ן ... הזינו פרטי כרטיס אשראי https://x.com` -> cant_verify, not dont_click. Link-less: `ב נ ק לאומי: התקשרו מיד ל 0501234567` fine only because the alias matched.
   Fix: unicodedata.normalize("NFKC") + casefold + confusables fold (Cyrillic/Greek/digits 1->l,0->o) on a shadow copy used for alias and signal matching; join runs of single letters ("ב נ ק") before matching; apply identically in Kotlin (java.text.Normalizer). Add to corpus.

4. MAJOR. Notification policy silences realistic scams: SMS `cant_verify` alerts only if an org is claimed (AgentCheck.kt shouldAlert / agent.py:should_alert).
   Repro: `החבילה שלך ממתינה https://evil.xyz/pay שלמו 5 ש"ח` (no brand named) -> cant_verify, claimed=[], no alert, History records quiet. An attacker simply omits the brand ("your parcel", "your account"). Same for strict chat apps: only certain+signal.
   Fix: alert on any cant_verify SMS that has a link on a shortener/bad TLD/non-common domain from an unknown sender with any pressure/payment signal; never treat "no org" as reassurance.

5. MAJOR. Local server has no Host/Origin check and no auth => DNS-rebinding and local-process abuse; also no timeouts.
   Repro: bind is 127.0.0.1 (server.py:main) but the handler never validates `Host`; a rebinding page (evil.test -> 127.0.0.1) is same-origin, so the JSON-content-type "CSRF" defence (server.py:_body comment) is moot: it can POST /api/settings {consented:true,name:..}, /api/handled (clears family alerts), /api/report (fabricate alerts) and GET /api/guardian (read events/hosts). Slowloris: `Content-Length: 60000` then stop sending -> `rfile.read(n)` blocks the thread forever (no socket timeout, unbounded threads). /api/check stores unbounded host in DB.
   Fix: reject requests whose Host is not localhost/127.0.0.1:port; reject non-matching Origin when present; per-install random token (header) required for all POST and /api/guardian; `self.timeout = 10`; cap threads; cap host length in record(); add security headers (X-Content-Type-Options, frame-ancestors/X-Frame-Options, CSP). Note the phone-to-server path (README/docs) contradicts a 127.0.0.1 bind: documented LAN use implies someone will bind 0.0.0.0 with zero auth; add a warning and refuse without the token.

6. MAJOR. Android guardian channel: cleartext + unauthenticated + metadata leak.
   AndroidManifest.xml:11 usesCleartextTraffic=true and GuardianClient.kt:18 prefixes http:// by default: anyone on the LAN/cafe wifi can read "this person got a certain scam from org X, host Y" or forge /api/report. History.kt comment "never stores ... the sender" is true, but GuardianClient sends link host (message-derived, can embed victim identifiers in subdomains/paths-free hosts) and `certain`; the doc privacy claim for the family channel should say "link host is sent". Notifier.kt lacks setVisibility(VISIBILITY_PRIVATE): lock screen shows "scam from bank" headline to bystanders (minor).
   Fix: HTTPS only (network_security_config; allow cleartext only in debug flavor), pin/bearer token, send hostname registrable-part only or hash, state it in consent text; setVisibility(PRIVATE) with public version.

7. MAJOR. Directory trust model is a flat JSON with no provenance enforcement or integrity.
   directory.json is hand-edited; `verified` is a bare boolean, `source` free text ("TO VERIFY" entries exist: tax_authority, kvish6, paypal, bit, home_front_command, israel_police_fines partially). One merged PR flipping `verified:true`, adding a domain (e.g. a typo) or a broad `common_domains` entry (waze.com, github.com, facebook.com, youtube.com are skipped as "not checked" and downgrade lookalike checks only if no token hit) makes phishing => matches_official. `common_domains` registrable match means `evil.github.com`/any github.io-like user-content (`registrable(host) in common` trusts every subdomain: e.g. attacker.github.com is not real but `*.googleusercontent`-style hosts) => cant_verify instead of dont_click when no brand token. Two copies (shomer/data and app/app/assets) are manually synced; I diffed: identical now but nothing in CI enforces it. gov.il is simultaneously official for israel_police_fines (verified) and tax_authority (unverified): _official_match picks the first, so tax-related claim + gov.il link -> "message shows a different org" (wrong, harmless) but shows the ambiguity. Update path: none shipped (assets bundled at build) so a revoked/poisoned entry cannot be fixed on installed phones.
   unconfirmed_domains: correctly never official/lookalike, but a lookalike such as `leumicard.co.il.evil.test` is caught only because the unconfirmed check requires exact/suffix match; OK. Weakness: `leumicard.co.il` is cant_verify even with `בנק לאומי` claim + pressure (never dont_click) - acceptable but attacker who registers unconfirmed-looking compromise stays soft.
   Fix: schema validation in CI (verified:true requires source URL on the org's own https domain + `verified_on` date + reviewer); CI test that the two copies are byte-identical (or build copies at gradle time); forbid verified domains on public-suffix-like/shared hosts; signed (ed25519) directory with version + expiry and a pinned key in the app for the update path, with rollback protection; remove `common_domains` subdomain trust (exact host only) or put them under neutral list.

8. MINOR. Percent-encoded NUL/odd host chars treated as host: `https://evil.test%00.leumi.co.il` -> matches_official (host kept as "evil.test%00.leumi.co.il", suffix match). Browsers reject it but link handlers/SMS apps may differ. Fix: after parse, reject hosts with chars outside [a-z0-9.-] (allowing IDN) => dont_click; decode %XX in host first.

9. MINOR. IDN: fullwidth/ideographic dot `israelpost。co。il` and `evil.test。com` are treated as a single odd host (dont_click only because non-ASCII flagged). A legitimate-looking `leumi.co.il` typed with U+3002 reaches browsers as the real domain and Android linkifiers; engine says dont_click so safe-side; but the reverse (`evil。leumi.co.il` equivalents) is covered. Fix: UTS46 map (replace U+3002/FF0E/FF61 with '.') before host compare, then punycode via `idna`; report the punycode form to user.

10. MINOR. Scams without recognized URL syntax pass quiet: `evil dot test`, `evil. test`, `www․evil․com` (U+2024), `evil(dot)com`, `בנק לאומי: צרו קשר ב-WhatsApp 050 123 45 67` or spaced digits `0 5 0 ...` => cant_verify/not alerted; phone regex needs contiguous digits (engine.py _PHONE_RE) and phone only counts when org claimed (score +1). QR (`סרקו את הקוד ושלמו`) with no org -> verdict cant_verify, applicable=False, headline "לא מצאנו סימן חשד" (a scan-QR payment demand is the textbook quishing lure; `payment` weight 1 alone doesn't reach applicable). wa.me/t.me links to unknown handles get dont_click only when an org is claimed. Fix: strip digit separators before phone match; treat "dot/נקודה/(dot)" as defang; any QR/payment+callback instruction => applicable with at least cant_verify and a "do not scan" reason; shorten-redirector hosts (wa.me, t.me, forms.gle, sites.google.com, docs.google.com) need explicit class "free hosting/chat link, cannot be an organization".

11. MINOR. Redirectors on common domains are trusted as "known site": `l.facebook.com/l.php?u=evil.test` -> cant_verify (OK) but never dont_click; `google.com/url?q=` only dont_click because of org claim. Fix: known open-redirect list => cant_verify with "this link forwards elsewhere".

12. MAJOR (claim "never says safe"). Mostly upheld in text (headlines hedge; no green; MATCHES_OFFICIAL not alerted), but: (a) the not-applicable result returns verdict `cant_verify` with headline "לא מצאנו סימן חשד" - given findings 3, 4, 10, many real scams land here and the first words read as reassurance; (b) MATCHES_OFFICIAL headline starts with "הכתובת היא של האתר הרשמי" and the share text "בדקתי הודעה עם שומר. התוצאה: ..." forwards a possibly-reassuring headline out of context; (c) matches_official on redirectors (finding 1) is the worst case: app says "official" for an attacker URL; (d) Notifier.kt:23 gives MATCHES_OFFICIAL an empty icon (only reachable if shouldAlert changes). Fix: lead not-applicable headline with "לא בדקנו" (could not assess) not "no sign of suspicion"; add the unspaced-obfuscation/long-input fallback "partial check" state; put "זה לא אישור" first for MATCHES; add a test asserting no result string contains words like "בטוח/תקין/מאושר" without negation.

13. MINOR. Logging: SmsReceiver/AgentCheck log lengths/verdicts to logcat in production (Log.i "ShomerE2E") - no content, but remove or guard by BuildConfig.DEBUG. AgentCheck keeps hashCode() of text in memory (collision lets a scammer craft a message that collides with a previously-seen benign one and be dropped silently: String.hashCode is trivially collidable, e.g. "Aa" vs "BB"). Fix: SHA-256 (truncated) key, and dedupe on (hash, verdict) only for non-alerts.

14. MINOR. Threat model (docs/PRD.md) is thin: no section naming attackers or abuse cases. grep finds no coverage of: homoglyph/IDN, open redirects, QR phishing, callback/vishing, voice-clone family scams, SIM-swap/OTP relay, compromised legitimate sender (the PRD itself cites a scam inside a genuine GOV.IL SMS thread, yet matches_official on sender-thread cannot detect it), directory poisoning, guardian-channel abuse (stalkerware: a "family monitor" with notification access is dual-use), notification-listener as high-value target, Play policy on RECEIVE_SMS, RCS/Unicode-spoofed contacts, adversarial ML-evasion of keyword signals (acknowledged only as "unusual wording can be missed"), DoS via long input.
   Fix: add a STRIDE-style table (asset, attacker, vector, mitigation, residual, test id) and make each REJECT above a regression test; define coverage claims in miss-rate terms (PRD itself notes 25 samples cannot show <12%).

Priority fix order: 1, 2, 3, 4, 5, then 7 and 6.
